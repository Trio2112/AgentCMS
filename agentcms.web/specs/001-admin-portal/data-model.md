# Data Model: AgentCMS Admin Portal

**Feature**: AgentCMS Admin Portal  
**Date**: February 13, 2026  
**Purpose**: Define entity structures, validation rules, relationships, and state transitions for admin portal

## Entity Overview

The admin portal manages three core entities: **Sites**, **Pages**, and **Assets**. These entities are stored and managed by the backend API; the frontend consumes them via REST endpoints.

### Entity Relationship Diagram

```
Site (1) ───────< (N) Page
  │                     │
  │                     │
  │                 (M) │
  │                     │
  └─────< (N) Asset ───┘
                    (N)
```

**Relationships**:
- One Site contains many Pages
- One Site contains many Assets  
- One Page can have many Assets (many-to-many via page-asset association)
- Each Page and Asset belongs to exactly one Site

## Site Entity

**Purpose**: Logical grouping for pages and assets. Represents a distinct website or content collection.

### Fields

| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| `id` | UUID | Yes (auto) | Read-only | Unique identifier, generated by API |
| `name` | String | Yes | 1-255 chars | Display name of the site |
| `description` | String | No | 0-255 chars | Optional description/notes |

### Validation Rules

- **FR-020**: `name` is required before save
- **name**: Must not be empty or whitespace-only
- **name**: Maximum 255 characters (per API contract in swagger.json)
- **description**: Optional, maximum 255 characters

### Frontend TypeScript Type

```typescript
// types/Site.ts
export interface Site {
  id: string              // UUID
  name: string            // Required, 1-255 chars
  description: string | null
}

export interface CreateSiteDto {
  name: string            // Required
  description?: string | null
}

export interface UpdateSiteDto {
  name: string            // Required
  description?: string | null
}

// Zod validation schema
import { z } from 'zod'

export const SiteSchema = z.object({
  name: z.string()
    .min(1, 'Site name is required')
    .max(255, 'Site name must be 255 characters or less')
    .trim(),
  description: z.string()
    .max(255, 'Description must be 255 characters or less')
    .optional()
    .nullable(),
})
```

### State Transitions

Sites have no state transitions; they are always active once created. Deletion is supported by the API (DELETE endpoint in swagger.json).

## Page Entity

**Purpose**: Represents a content page within a site, with support for scheduled publishing.

### Fields

| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| `id` | UUID | Yes (auto) | Read-only | Unique identifier, generated by API |
| `siteId` | UUID | Yes | Read-only | Parent site ID, set on creation |
| `title` | String | Yes | 1-255 chars | Page title |
| `body` | String | No | Unlimited | Page content (plain text or markdown) |
| `publishedDate` | DateTime | No | ISO 8601, nullable | Publication date for scheduling |
| `isPublished` | Boolean | Yes (computed) | Read-only | Computed from publishedDate |
| `createdDate` | DateTime | Yes (auto) | Read-only | Creation timestamp |
| `updatedDate` | DateTime | Yes (auto) | Read-only | Last modification timestamp |
| `createdBy` | String | No | 0-255 chars | Username/email of creator |
| `updatedBy` | String | No | 0-255 chars | Username/email of last editor |

### Validation Rules

- **FR-019**: `title` is required before save
- **title**: Must not be empty or whitespace-only
- **title**: Maximum 255 characters
- **body**: Optional, no length limit (stored as text column in DB)
- **publishedDate**: Must be valid ISO 8601 datetime if provided; nullable for unpublished pages
- **FR-021**: Future `publishedDate` values are valid (scheduled publishing)

### Computed Field: `isPublished`

**FR-002**: `isPublished` is computed based on `publishedDate`:

```typescript
const computeIsPublished = (publishedDate: string | null): boolean => {
  if (!publishedDate) return false
  return new Date(publishedDate) <= new Date() // Compare to current time
}
```

**Logic**:
- `publishedDate === null` → `isPublished = false` (Unpublished)
- `publishedDate <= now()` → `isPublished = true` (Published)
- `publishedDate > now()` → `isPublished = false` (Scheduled)

### Frontend TypeScript Type

```typescript
// types/Page.ts
export interface Page {
  id: string
  siteId: string
  title: string
  body: string | null
  publishedDate: string | null    // ISO 8601 datetime
  isPublished: boolean            // Computed, read-only
  createdDate: string             // ISO 8601 datetime
  updatedDate: string             // ISO 8601 datetime
  createdBy: string | null
  updatedBy: string | null
}

export interface CreatePageDto {
  title: string                   // Required
  body?: string | null
  publishedDate?: string | null   // ISO 8601 datetime
  createdBy?: string | null
}

export interface UpdatePageDto {
  title: string                   // Required
  body?: string | null
  publishedDate?: string | null   // ISO 8601 datetime OR explicitly null to unpublish
  updatedBy?: string | null
}

// Zod validation schema
import { z } from 'zod'

export const PageSchema = z.object({
  title: z.string()
    .min(1, 'Page title is required')
    .max(255, 'Page title must be 255 characters or less')
    .trim(),
  body: z.string()
    .optional()
    .nullable(),
  publishedDate: z.string()
    .datetime({ message: 'Invalid date format' })
    .optional()
    .nullable(),
})
```

### State Transitions

Pages transition between three publication states:

```
┌─────────────┐
│ Unpublished │ (publishedDate = null)
│ isPublished │
│   = false   │
└──────┬──────┘
       │
       │ Set publishedDate to now or past
       ↓
┌─────────────┐
│  Published  │ (publishedDate <= now)
│ isPublished │
│   = true    │
└──────┬──────┘
       │
       │ Set publishedDate to future
       ↓
┌─────────────┐
│  Scheduled  │ (publishedDate > now)
│ isPublished │
│   = false   │
└──────┬──────┘
       │
       │ (Time passes, publishedDate becomes past)
       ↓
┌─────────────┐
│  Published  │
└─────────────┘
```

**Unpublishing** (FR-003):
- Set `publishedDate = null` → page becomes Unpublished
- API must accept `null` value for `publishedDate` in UpdatePageDto

## Asset Entity

**Purpose**: Represents an uploaded file or external URL resource associated with pages.

### Fields

| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| `id` | UUID | Yes (auto) | Read-only | Unique identifier, generated by API |
| `siteId` | UUID | Yes | Read-only | Parent site ID |
| `filename` | String | Yes | 1-500 chars | Original filename or generated name |
| `mimeType` | String | Yes | Valid MIME type | Content type (e.g., "image/jpeg") |
| `url` | String | Yes | Valid URL | Storage URL or external URL |
| `createdDate` | DateTime | Yes (auto) | Read-only | Upload/creation timestamp |
| `createdBy` | String | No | 0-255 chars | Username/email of uploader |

### Validation Rules (Frontend, Pre-Upload)

**FR-022/FR-023**: Client must validate **before** initiating upload:

- **File Size**: Maximum 10MB (10 * 1024 * 1024 bytes)
- **MIME Type Whitelist**:
  - Images: `image/jpeg`, `image/png`, `image/gif`, `image/webp`
  - Documents: `application/pdf`
  - HTML: `text/html`
  - (Additional types can be added based on product requirements)

**Validation Logic**:
```typescript
const ALLOWED_MIME_TYPES = [
  'image/jpeg',
  'image/png',
  'image/gif',
  'image/webp',
  'application/pdf',
  'text/html',
]
const MAX_FILE_SIZE = 10 * 1024 * 1024 // 10MB

export const validateFile = (file: File): { valid: boolean; error?: string } => {
  if (!ALLOWED_MIME_TYPES.includes(file.type)) {
    return { 
      valid: false, 
      error: `Unsupported file type: ${file.type}. Allowed types: ${ALLOWED_MIME_TYPES.join(', ')}` 
    }
  }
  if (file.size > MAX_FILE_SIZE) {
    const sizeMB = (file.size / 1024 / 1024).toFixed(2)
    return { 
      valid: false, 
      error: `File size (${sizeMB}MB) exceeds 10MB limit` 
    }
  }
  return { valid: true }
}
```

## Page-Asset Association (Many-to-Many)

**Purpose**: Links assets to pages for display or download on the public site.

### Association Model

**Note**: The existing API (per swagger.json) does not explicitly show page-asset association endpoints. This is **likely missing** and must be added to the API.

**Required API Endpoints** (not in current swagger.json):
```
POST   /v1/sites/{siteId}/pages/{pageId}/assets/{assetId}  # Add association
DELETE /v1/sites/{siteId}/pages/{pageId}/assets/{assetId}  # Remove association
GET    /v1/sites/{siteId}/pages/{pageId}/assets            # List associated assets
```

### Frontend Data Structure

```typescript
// types/PageAsset.ts
export interface PageAssetAssociation {
  pageId: string
  assetId: string
  createdDate: string    // When association was created
}

// Extended Page type with assets
export interface PageWithAssets extends Page {
  assets: Asset[]
}
```

### Business Rules

- **FR-009**: A page can have 0 or more associated assets
- **FR-010**: Removing an asset from a page does NOT delete the asset; only the association is removed
- **No Ordering**: Asset order is not specified in requirements; display in creation order or alphabetically
- **No Duplicate Associations**: A page-asset pair can only exist once (enforce in UI and API)

## Concurrent Edit Detection

**Mechanism**: Use `updatedDate` field on Page entity.

### Detection Logic

```typescript
// Store original updatedDate when page is loaded for editing
const [originalUpdatedDate, setOriginalUpdatedDate] = useState<string | null>(null)

useEffect(() => {
  if (page) {
    setOriginalUpdatedDate(page.updatedDate)
  }
}, [page])

// Before save, check if page was modified by another user
const checkForConcurrentEdit = async (pageId: string): Promise<boolean> => {
  const currentPage = await fetchPage(pageId)
  
  if (currentPage.updatedDate !== originalUpdatedDate) {
    const proceed = window.confirm(
      `This page was modified by ${currentPage.updatedBy || 'another user'} ` +
      `at ${new Date(currentPage.updatedDate).toLocaleString()}. ` +
      `Your changes will overwrite theirs. Continue?`
    )
    return proceed
  }
  
  return true // No conflict
}
```

**FR-024/FR-025/FR-026**: Last save wins, with warning to user before overwrite.

## API Contract Gaps (Backend Changes Needed)

Based on the swagger.json analysis, the following changes are required to the backend API to support the spec requirements:

### 1. Add `publishedDate` to Page Entity (**CRITICAL**)

**Current**: PageDto has `isPublished: boolean`
**Required**: 
```json
{
  "publishedDate": {
    "type": "string",
    "format": "date-time",
    "nullable": true
  },
  "isPublished": {
    "type": "boolean",
    "readOnly": true,
    "description": "Computed from publishedDate"
  }
}
```

**Impact**: Without this, scheduled publishing (FR-021) cannot be implemented.

### 2. Add Page-Asset Association Endpoints (**HIGH PRIORITY**)

**Missing Endpoints**:
- `POST /v1/sites/{siteId}/pages/{pageId}/assets/{assetId}`
- `DELETE /v1/sites/{siteId}/pages/{pageId}/assets/{assetId}`
- `GET /v1/sites/{siteId}/pages/{pageId}/assets`

**Impact**: Without these, User Story 3 (Associate Assets with Pages) cannot be implemented.

### 3. File Upload Endpoint

**Existing**: `POST /v1/sites/{siteId}/assets` likely accepts multipart/form-data (not documented in swagger)
**Required**: Confirm endpoint accepts:
```
Content-Type: multipart/form-data
Body:
  file: <binary data>
  createdBy: <string>
```
